5. Security-Sensitive Fields and Constraints
Authentication Credentials:

User.password: Stored as a salted bcrypt hash (bcrypt.hash(password, 12)) (

server/controllers/user.js:57,145
).
User.resetToken & User.expireToken: 32-byte cryptographic hex token with a 1-hour expiration timestamp (Date.now() + 3600000) (

server/controllers/user.js:107,114
).
Ownership & Identity Scoping Fields:

InvoiceModel.creator (

server/models/InvoiceModel.js:15
)
ClientModel.userId (

server/models/ClientModel.js:9
)
Profile.userId (

server/models/ProfileModel.js:12
)
Code Enforcement Reality: These fields are never validated against a verified session or JWT token on the server. They are accepted directly from the client's req.body or filtered via unauthenticated req.query.searchQuery parameters.
Financial, Billing & Payment Information:

Profile.paymentDetails: Raw text string storing banking/payment instructions (

server/models/ProfileModel.js:9
).
InvoiceModel.total, subTotal, vat, rates, totalAmountReceived: Financial figures accepted directly from client payload without server-side mathematical verification (

server/controllers/invoices.js:55-60,83-87
).
InvoiceModel.paymentRecords: Array tracking payments (amountPaid, datePaid, paymentMethod, paidBy, note) (

server/models/InvoiceModel.js:18
).
Client PII:

ClientModel.email, ClientModel.phone, ClientModel.address, and embedded InvoiceModel.client (

server/models/ClientModel.js:5-8
, 

server/models/InvoiceModel.js:17
). Accessible system-wide via GET /clients (

server/controllers/clients.js:45
).
